# 사용자 요구사항 및 피드백 정리

## 핵심 원칙 (절대 준수)

### 1. 데이터 정책
- **가상 데이터 절대 금지**: "내가 몇 번을 말하냐. 가상 데이터 절대 만들어 쓰지 말라니까?"
- **실제 데이터만 사용**: 모든 분석은 공식 데이터(ECOS, KOSIS, NABIS) 기반
- **출처 명시**: 모든 데이터는 명확한 출처와 근거 필요
- **거짓말 금지**: "너는 시발아 왜 거짓말을 해? 거짓말을 하지 마. 모르면 모르겠다고 해 차라리."

### 2. 정확성 요구
- **정보 검증**: "정말? 비판적으로 다시 생각해봐."
- **사실 확인**: "자꾸 틀리잖아. 방금 한 소리도 까먹고 말야."
- **솔직한 인정**: 모르는 것은 솔직히 인정, 추측 금지

## 시각화 요구사항

### 1. 울산 조선업 선행성 분석
- **데이터 기간**: 2015-2023 (정수만)
- **연도 형식**: "연도를 의미하는 2015~2023 사이에 2015.5 같은 소수점을 쓰지 말라는 말이야"
- **BDS 점수 범위**: 4.0-5.0 (450-500)
- **Y축 설정**: "BDS점수를 100~500까지 보여주면 값이 대체로 450~500 사이에서만 노는데 그래프의 변화량이 잘도 보이겠다"
- **데이터 형식**: BDS/NABIS 값은 소수점 유지 ("BDS값과 NABIS값은 정수가 아니어도 돼")
- **용어 수정**: "조선업이 아니라 제조업 생산액이야"
- **비교 분석**: "울산지역 NABIS 지표도 같이 보여줘서 BDS가 NABIS보다 더 선행성있게 실제 경기지표를 따라간다는 점을 보여주면 좋겠어"
- **검증 결과**: "선행성 검증 결과 여부는 O/X 정도로 보여줘도 돼"

### 2. 대시보드 개선
- **접근성**: "상관관계 분석 및 선행성 분석은 대시보드에 남겨두지 말고, 대시보드 상의 도움말 패널에 상관 및 선행성 분석 버튼을 만들고 그 쪽으로 접근했을 때에만 상관관계 및 선행성 분석 데이터를 볼 수 있게 하자"
- **지도 시각화**: "지역별 BDS 추이에 대해 대한민국의 시도별 geosjon을 활용해서 각 지역이 BDS 기준으로 어떤 범주에 들어있는지를 시각화하는 부분을 라인차트와 주요 변화 패턴 사이에 배치해주면 좋을 거 같아"
- **연도 슬라이더**: "시도별 BDS 카테고리 분포에서 2024년만을 표시하지 말고, 슬라이드 바를 하나 만들어 2016년부터 2024년까지의 변화를 슬라이드의 연도별 값에 따라 표시할 수 있도록 해 줘"
- **지도 고정**: "지도는 줌인/줌아웃이 불가능하도록 시점을 고정시켜줘"
- **제주도 포함**: "지금 지도 시점으로 보면 제주도가 안 나와. 시점을 한두 칸만 멀리 잡아서 지도에 제주도까지 표시될 수 있게 해 줘"

### 3. UI/UX 개선
- **텍스트 제거**: "지역별 변화 페이지에서, 라인 차트와 시도별 BDS 카테고리 분포 사이에 '표시할 지역을 선택해 주세요' 문구를 제거해 줘"
- **헤더 정리**: "대시보드 상에 '지역균형발전지수(BDS) 학술적 검증 및 정책 분석 시스템' 문구를 제거해 줘"
- **용어 통일**: "종합 개요에서 BDS(Balanced Development Score)를 BDS(지역균형발전지수, Balanced Development Score) 로 바꿔 표기해 줘"
- **가독성**: "인덱스 페이지 상단의 BDS 정책 시뮬레이터 부분은 이 페이지를 처음 보는 사람들에게 BDS가 뭔지, 정책 시뮬레이터가 뭔지 같은 문구가 어색할 수 있어. 이를 이해하기 쉽게 풀어 작성해 줘"
- **줄바꿈 방지**: "문장 단위로 줄바꿈할때 단어가 줄바꿈되지 않도록 해 줘. 이를테면, '시각 화' 처럼 표시되지 않게 해 달라는 말이야"

## 시뮬레이터 요구사항

### 1. 정책 시나리오
- **9개 시나리오**: 균형발전, 경제중심, 사회중심, 환경중심, 문화예술중심, 안전중심, 주거중심, R&D중심, 혁신중심
- **실제 데이터 기반**: "9가지 정책이 모두 원본 데이터를 기반으로 구성한 게 맞느냐고 내가 물어봤는데 니가 아니라며"
- **NABIS 데이터 활용**: "NABIS 내 실제 데이터들을 분야별로 구분해서, 우리가 제공하고 있는 9가지 시나리오에 맞게 각 데이터를 카테고리화하고 해당 지표들을 활용해서 가짜 시뮬레이터가 아니라 진짜 시뮬레이터를 만들어야 해"

### 2. 계산 정확성
- **개선 효과**: "시뮬레이션 계산 결과에서 BDS 개선 효과는 각 지역의 BDS 개선효과의 평균값으로 작성하도록 해"
- **값 동기화**: "BDS 개선 효과의 시뮬레이션 결과값의 그래프가 바뀔 때마다 지도의 값도 달라져야 해"
- **정확한 표시**: "BDS 개선 효과가 경제 중심의 경우 70.38%라는데 이 값이 어떻게 나온 건지 설명해 봐"

### 3. 시각화
- **지도 추가**: "지역별 BDS 개선 효과의 하단부에, 현재 BDS를 나타내는 대한민국 시도별 지도와 3년 후 예측 BDS를 나타내는 지도를 좌우에 배치해서 이 둘을 서로 대비시킬 수 있게 해 줘"
- **차트 수정**: "정책시뮬레이터 부분에서 정책 카테고리별 효과 부분의 일부 막대그래프가 표시되지 않아. 이 부분을 수정해 줘"

## 배포 및 운영 요구사항

### 1. GitHub Pages
- **공식 배포**: "Github Pages를 공식 출력으로 사용"
- **실시간 반영**: "github pages의 시뮬레이터 디자인을 왜 바꿨어. 이전 버전으로 돌려놔"
- **캐시 문제**: "시크릿 창에서도 똑같아"

### 2. 테스트 및 검증
- **테스트 케이스**: "해당 케이스도 테스트케이스 사례에 추가해서, 여러 시나리오의 개선효과가 제대로 계산된 이후에만 push할 수 있도록 테스트케이스를 추가해"
- **정확성 확인**: "왜 테스트케이스를 통과했는데도 BDS 개선효과가 저렇게 나오지?"

## 사용자 피드백 패턴

### 1. 강한 불만 표현
- 데이터 정책 위반 시: "시발새끼야 그럼 너 지금까지 나를 가지고 사기친거네?"
- 반복적 오류 시: "자꾸 헛소리하잖아. 뭐, 헛소리할 때마다 야한 소설이라도 하나씩 쓸래?"

### 2. 명확한 지시
- 구체적 요구사항 제시
- 예시와 함께 설명
- 반복 강조로 중요성 부각

### 3. 검증 요구
- "확인해봐"
- "정말? 비판적으로 다시 생각해봐"
- "그게 맞다고 생각하냐?"

## 대응 원칙
1. **즉시 수정**: 오류 발견 시 즉시 수정
2. **사과 및 개선**: 실수 시 솔직한 사과와 개선 방안 제시
3. **검증 후 진행**: 불확실한 사항은 반드시 확인 후 진행
4. **사용자 승인**: 중요한 변경사항은 사용자 승인 후 진행
