# NABIS Contest 프로젝트 전체 요약 및 핵심 사항

## 프로젝트 개요
- **프로젝트명**: 지역균형발전지수(BDS) 학술적 검증 및 정책 분석 시스템
- **목적**: NABIS 공모전을 위한 BDS 지수의 학술적 검증 및 정책 시뮬레이션 시스템 구축
- **핵심 기능**: BDS 대시보드, 정책 시뮬레이터, 재정자립도 분석, 울산 조선업 선행성 분석

## 사용자 강조사항 및 핵심 요구사항

### 1. 데이터 정책 (절대 준수)
- **가상 데이터 절대 금지**: 모든 분석은 실제 데이터만 사용
- **데이터 출처 명시**: 모든 데이터는 명확한 출처와 근거 필요
- **거짓말/사기 금지**: 모르는 것은 솔직히 인정, 추측 금지

### 2. 시각화 요구사항
- **연도 표시**: 2015-2023 (정수만, 소수점 금지)
- **BDS 점수 범위**: 4.0-5.0 (또는 450-500)
- **데이터 형식**: BDS/NABIS 값은 소수점 유지
- **검증 결과**: O/X 형태로 표시

### 3. 시뮬레이터 요구사항
- **9개 정책 시나리오**: 균형발전, 경제중심, 사회중심, 환경중심, 문화예술중심, 안전중심, 주거중심, R&D중심, 혁신중심
- **RDI 기반**: NABIS 지역발전지수 구조 활용
- **실제 데이터 기반**: NABIS 객관지표 데이터 활용
- **정확한 계산**: 개선 효과는 각 지역의 평균값으로 계산

### 4. 배포 및 운영
- **GitHub Pages**: 공식 배포 플랫폼
- **실시간 동기화**: 로컬 변경사항이 즉시 반영되어야 함
- **디자인 일관성**: 의도하지 않은 디자인 변경 금지

## 핵심 해결 과제

### 1. 데이터 무결성 확보
- ECOS, KOSIS, NABIS 등 공식 데이터만 사용
- 가상 데이터 생성 및 사용 완전 금지
- 모든 데이터의 출처와 기간 명확히 문서화

### 2. 시뮬레이터 정확성
- BDS 개선 효과 계산 로직 검증
- 시나리오별 정확한 개선 효과 표시
- 지도 시각화와 시뮬레이션 결과 동기화

### 3. 사용자 경험 최적화
- 직관적인 인터페이스
- 명확한 데이터 표시
- 반응형 디자인

## 기술 스택
- **Frontend**: HTML5, CSS3, JavaScript (ES6+)
- **차트 라이브러리**: Plotly.js
- **지도 라이브러리**: Leaflet.js
- **스타일링**: Bootstrap 5
- **데이터 형식**: JSON
- **배포**: GitHub Pages

## 주요 파일 구조
```
/NABIS_contest/
├── bds_enhanced_dashboard.html      # 메인 BDS 대시보드
├── bds_simulator.html              # 정책 시뮬레이터
├── index.html                      # 프로젝트 랜딩 페이지
├── data/                          # 데이터 저장소
│   ├── bds/                       # BDS 관련 데이터
│   ├── ecos/                      # ECOS 데이터
│   ├── kosis/                     # KOSIS 데이터
│   ├── nabis/                     # NABIS 데이터
│   └── simulation_results/        # 시뮬레이션 결과
├── scripts/                       # 데이터 처리 스크립트
├── simulators/                    # 시뮬레이터 로직
└── docs/                         # 문서화
```
